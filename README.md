# О проекте LINGWARD

> **LINGWARD** — *от Language (язык) и ward (направление, сторона)*.  
> **Ваш проводник в мир иностранных языков**.

**LINGWARD** — это открытая платформа для онлайн-обучения иностранным языкам, объединяющая репетиторов и учеников. Проект создан как пример современного веб-приложения для студентов и как реальный инструмент для запуска бизнеса. В перспективе его можно будет использовать для онлайн обучения в любой предметной области, привлекая современные технологии и возможности AI.

---

## 🎯 Цели проекта

1. **Снизить издержки репетиторов** на администрирование (расписание, репетиторы, ученики, сервисы видеоконференцсвязи, интерактивных досок и платежей).
2. **Повысить вовлеченность учеников** через ИИ-инструменты и геймификацию.
3. **Создать образовательный стенд** для студентов, изучающих web-технологии, на основе которого они смогут строить свои дипломные проекты.
4. **Построить расширяемую архитектуру**, позволяющую заменять внешних провайдеров (ВКС, доски, AI, платежи) без переписывания ядра.

### Ключевые архитектурные слои

| Слой                    | Назначение                                        | Расширяемость                                           |
| :---------------------- | :------------------------------------------------ | :------------------------------------------------------ |
| **Ядро (core/)**        | Настройки, события, базовые маршруты              | Не изменяется. Новые фичи добавляются через события.    |
| **Приложения (apps/)**  | Бизнес-логика (CRM, Биллинг, Доска, ВКС)          | Добавление нового приложения не требует изменения ядра. |
| **Сервисы (services/)** | Абстракция внешних провайдеров (ВКС, AI, платежи) | Смена провайдера — изменение одной строки в `.env`.     |
| **API (api/)**          | Версионированные эндпоинты для фронтенда          | Новая версия API создаётся без изменения старых.        |

### Абстракция провайдеров (Services)

Все внешние сервисы подключаются через **интерфейсы** (`services/interfaces/`). Конкретные реализации лежат в `services/providers/`. Фабрика (`factory.py`) выбирает нужного провайдера на основе настроек в `.env`.

**Поддерживаемые (в перспективе) типы провайдеров:**

| Тип           | Community Edition   | Commercial Edition             |
| :------------ | :------------------ | :----------------------------- |
| **ВКС**       | Jitsi (self‑hosted) | Jitsi + Salute Jazz            |
| **Доски**     | Excalidraw          | Excalidraw + Interboard + Miro |
| **AI‑агенты** | Mock (заглушка)     | GigaChat, YandexGPT, DeepSeek  |
| **Платежи**   | Mock (тестовый)     | ЮKassa, Stripe                 |

## 🛡️ Защита коммерческого кода и конфигураций

В проекте используется **двухуровневая стратегия** защиты коммерческой части (`-wl` файлов):

1. **Компиляция в бинарный код**: Все файлы с суффиксом `-wl` (включая провайдеров и конфигурации) компилируются в нативные бинарные модули (`.pyd` / `.so`) с использованием **Cython (Python Binary Optimization Compiler)**. Это обеспечивает полное сокрытие исходного кода, прирост производительности и невозможность декомпиляции в читаемый Python-код.

2. **Разделение конфигураций**: Конфигурационные файлы для продакшена (`config/production-wl.py`) также компилируются и распространяются только в составе Commercial Edition. В Community Edition используется открытая конфигурация `config/base.py` с SQLite и настройками для разработки.

### База данных

| Версия                 | СУБД по умолчанию | Примечание                                                   |
| :--------------------- | :---------------- | :----------------------------------------------------------- |
| **Community Edition**  | SQLite            | Используется по умолчанию для простоты запуска. Вы можете вручную подключить любую СУБД, поддерживаемую Django (включая PostgreSQL), но мы не предоставляем готовых конфигураций и оптимизаций. |
| **Commercial Edition** | PostgreSQL 16     | Рекомендуемая и поддерживаемая СУБД. Включает готовые конфигурации, оптимизации, управление миграциями и бэкапами. |

Переключение на PostgreSQL осуществляется через переменную окружения `DATABASE_URL`, но для Commercial Edition мы также предоставляем полный набор настроек и инструкций.

## 🚀 Быстрый старт (для разработчиков)

### 1. Клонировать репозиторий
```bash
git clone https://github.com/pi3141592/lingward.git
cd lingward
```

### 2. Создать виртуальное окружение и активировать его

```
python -m venv .venv
source .venv/bin/activate  # Linux/Mac
.venv\Scripts\activate     # Windows
```

### 3. Установить зависимости

```
pip install -r requirements.txt
```

### 4. Настроить переменные окружения

Создайте файл `.env` в корне проекта: 

```
DJANGO_SECRET_KEY=your-secret-key
DEBUG=True
DATABASE_URL=sqlite:///db.sqlite3
```

### 5. Выполнить миграции и создать суперпользователя

```
python lingward/manage.py migrate
python lingward/manage.py createsuperuser
```

### 6. Запустить сервер разработки

```
python lingward/manage.py runserver
```

Откройте браузер и перейдите по адресу: http://127.0.0.1:8000/admin
